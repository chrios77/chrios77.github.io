```
1. private이 붙으면 어찌되는가? ⇒ private가 붙게 되면 해당 클래스 내부에서만 호출할 수 있다.
2. 접근 제어자가 있으면 뭐가 좋은가? ⇒ 클래스에 있는 데이터를 통제할 수 있다.
3. 자바는 몇 가지의 접근 제어자를 제공하는가? ⇒ private, default, protected, public이라는 4가지의 접근 제어자를 제공한다.
4. private, default, protected, public에 관해 설명해봐라. ⇒ private는 모든 외부 호출을 막고, default는 같은 패키지 안에서의 호출을 허용하며, protected는 같은 패키지 안에서 호출을 허용하고 패키지가 달라도 상속 관계의 호출은 허용하며, public은 모든 외부 호출을 허용한다.
5. 접근 제어자의 핵심은 무엇인가? ⇒ 접근 제어자의 핵심은 속성과 기능을 외부로부터 숨기는 것이다.
6. private? ⇒ private는 나의 클래스 안으로 속성과 기능을 숨길 때 사용하고, 외부 클래스에서 해당 기능을 호출할 수 없다.
7. default? ⇒ default는 나의 패키지 안으로 속성과 기능을 숨길 때 사용하고, 외부 패키지에서 해당 기능을 호출할 수 있다.
8. protected? ⇒ protected는 상속 관계로 속성과 기능을 숨길 때 사용하고, 상속 관계가 아닌 곳에서 해당 기능을 호출 할 수 없다. 
9. public? ⇒ public은 기능을 숨기지 않고 어디서든 호출할 수 있게 공개한다.
10. 접근 제어자는 어디에 사용할 수 있는가? ⇒ 클래스, 필드, 메소드
11. public 클래스는 반드시 파일명과 이름이 같아야 한다 O/X ⇒ O
12. 클래스 레벨의 접근 제어자는 public과 default만 사용할 수 있다. O/X ⇒ O
13. 하나의 자바 파일에 public 클래스는 하나만 존재할 수 있다 O/X ⇒ O
14. 하나의 자바 파일 안에 default 접근 제어자를 사용하는 클래스는 무한정 만들 수 있다 O/X ⇒ O
15. 캡슐화란 영어로 무엇이고, 뭘 말하는 것인가? ⇒ 캡슐화는 영어로 Encapsulation이라 하고 속성과 기능을 하나로 묶고, 외부에 꼭 필요한 기능만 노출하고 나머지는 모두 내부로 숨기는 것이다.
16. 캡슐화를 안전하게 완성할 수 있게 해주는 장치가 무엇인가? ⇒ 접근 제어자
17. 캡슐화를 통해 어떤 것을 숨기고 노출해야 하는가? ⇒ 데이터에서 가장 필수로 숨겨야 하는 것은 속성 즉, 데이터, 멤버 변수이다. 또한, 객체의 기능 중에서 외부에서 사용하지 않고 내부에서만 사용하는 기능들이 있는데 이런 기능도 모두 감추는 것이 좋다.
18. 객체 내부의 데이터를 외부에서 함부로 접근하게 두면 어찌되는가? ⇒ 객체 내부의 데이터를 외부에서 함부로 접근하게 두면 클래스 안에서 데이터를 다루는 모든 로직을 무시하고 데이터를 변경할 수 있기에 모든 안전망을 다 빠져나가게 된다. 그러면 결국 캡슐화가 깨진다. 따라서 객체의 데이터는 객체가 제공하는 기능인 메소드를 통해서 접근해야 한다.
19. 17번에서 메소드도 숨기라고 했는데 이게 무슨 소리인가? 데이터와 기능을 모두 숨기게 되는 것 아닌가? ⇒ 이 얘기는 가급적이면 필요한 기능만 오픈하라는 것이다. 
20. 그럼 캡슐화를 한 문장으로 얘기하면 무엇인가? ⇒ 데이터는 모두 숨기고, 기능은 꼭 필요한 기능만 노출하는 것.

```
1. 자바 메모리 구조는 크게 몇 가지로 나뉘는가? ⇒ 메소드 영역, 스택 영역, 힙 영역, 이렇게 3가지로 나눌 수 있다.
2. 메소드 영역, 스택 영역, 힙 영역은 각각 어떤 영역인가? ⇒ 메소드 영역은 클래스 정보를 보관하고 스택 영역은 실제 프로그램이 실행되는 영역이기에 메소드를 실행할 때 마다 하나씩 쌓인다. 힙 영역은 객체나 인스턴스가 생성 되는 영역으로, new 명령어를 사용하면 이 영역을 사용한다. 참고로 배열도 힙 영역에 생성된다.
3. 메서드 영역은 뭘 말하며, 뭘 관리하는가? ⇒ 메소드 영역은 영어로 method area라고 하고, 프로그램을 실행하는데 필요한 공통 데이터(클래스 정보, static 영역, 런타임 상수 풀)를 관리한다. 이 영역은 프로그램의 모든 영역에서 공유한다.
4. 클래스 정보란? ⇒ 클래스의 실행 코드인 바이트 코드, 필드, 메소드와 생성자 코드 등 모든 실행 코드가 존재한다.
5. static 영역이란? ⇒ static 변수들을 보관한다.
6. 런타임 상수 풀이란? ⇒ 프로그램을 실행하는데 필요한 공통 리터럴 상수를 보관한다. 프로그램을 효율적으로 관리하기 위해 상수들을 관리한다.
7. 스택 영역이란? ⇒ 영어로 statck area라고 하고, 자바 실행 시, 하나의 실행 스택이 생성된다. 각 스택 프레임은 지역 변수, 중산 연산 결과, 메소드 호출 정보 등을 포함한다. 더 정확히는 각 스레드별로 하나의 실행 스택이 생성된다. 따라서 스레드 수 만큼 스택 영역이 생성된다.
8. 스택 프레임이란? ⇒ 스택 영역에 쌓이는 것이 하나의 스택 프레임이다. 메소드를 호출할 때마다 하나의 스택 프레임이 쌓이고, 메소드가 종료되면 해당 스택 프레임이 제거된다.
9. 힙 영역이란? ⇒ 힙 영역은 영어로 heap area라고 하고 객체/인스턴스/배열이 생성되는 영역이다. 가비지 컬렉션(GC)이 이루어지는 주요 영역이며, 더 이상 참죄되지 않는 객체는 gc에 의해 제거된다.
10. 같은 클래스로부터 생성된 생성된 객체라도, 인스턴스 내부의 변수 값은 서로 다를 수 있지만, 메소드는 공통된 코드를 공유한다. 따라서 객체가 생성될 때, 인스턴스 변수에는 메모리가 할당되지만, 메소드에 대한 새로운 메모리 할당은 없다. 메소드는 메소드 영역에서 공통으로 관리되고 실행된다. 정리하면 인스턴스의 메소드를 호출하면 실제로는 메소드 영역에 있는 코드를 불러서 수행한다.
11. 자료 구조란? ⇒ 데이터를 어떤 식으로 보관하고 관리하는지에 대한 어떤 구조를 말한다.
12. 스택이란? ⇒ 스택은 영어로 stack이라고 한다. 스택이란 나중에 넣은 데이터가 가장 먼저 나오는 후입 선출, 즉, LIFO(Last In First Out)을 말한다. 프로그램 실행과 메소드 호출에는 스택 구조가 적합하다.
13. 큐란? ⇒ 큐는 영어로 queue라고 하고, 가장 먼저 넣은 것이 가장 먼저 나오는 것을 말하며 이를 선입 선출, FIFO(First In First Out)이라고도 한다. 선착순 이벤트를 하는데 고객이 대기해야 한다면 큐 자료 구조를 사용해야 한다.
14. 스택을 통해 자바는 뭘 하는가? ⇒ 자바는 스택 영역을 사용해서 메소드 호출과 매개변수를 포함한 지역변수를 관리한다. 메소드를 계속 호출하면 스택 프레임이 계속 쌓인다. 지역 변수는 스택 영역에서 관리하고 스택 프레임이 종료되면 지역 변수도 함께 제거되며 스택 프레임이 모두 제거되면 프로그램도 종료한다.
15. 결과적으로 프로그램에서 더는 사용하지 않는 객체는 뭘 말하는 것인가? ⇒ 참조하는 곳이 없으므로 사용되는 곳도 없다. 이런 객체는 메모리만 차지하기에 GC가 참조하고 모두 사라진 인스턴스를 찾아서 메모리에서 제거한다. 참고로 힙 영역 외부가 아닌, 힙 영역 안에서만 인스턴스끼리 서로 참조하는 경우에도 GC의 제거 대상이 된다.
16. static 키워드는 주로 어디에 사용되는가? ⇒ static 키워드는 주로 멤버 변수와 메소드에 사용된다.
17. static 키워드를 사용하면 뭘 할 수 있는가? ⇒ 특정 클래스에서 공용으로 함께 사용할 수 있는 변수를 만들 수 있다면 편리할 것이기에 static 키워드를 사용하면 공용으로 함께 사용하는 변수를 만들 수 있다.
18. 멤버 변수에 static 키워드를 붙이면 뭐라고 하는가? ⇒ static 변수, 정적 변수, 클래스 변수라고 한다.
19. static 키워드가 붙은 멤버 변수는 어디서 관리하는가? ⇒ 메소드 영역에서 관리한다.
20. 맴버 변수는 뭘로 분류가 되는가? ⇒  static 키워드가 붙지 않은 멤버 변수인 인스턴스 변수, static이 붙은 변수인 클래수 변수로 나뉜다.
21. 왜 인스턴스 변수라고 하는가? ⇒ static 키워드가 안 붙은 변수는 인스턴스를 생성해야 사용할 수 있고, 인스턴스에 소속되어 있기에 인스턴스 변수라고 한다.
22. 클래스 변수는 다른 말로 뭐라고 하는가? ⇒ 정적 변수, static 변수 등으로 불린다.
23. 왜 클래스 변수라고 하는가? ⇒ static 키워드가 붙은 멤버 변수는 인스턴스와 무관하게 클래스에 바로 접근해서 사용할 수 있고, 클래스 자체에 소속되어 있기에 클래스 변수라고 한다.
24. 자바에서 클래스 변수는 어떻게 된는가? ⇒ 자바에서 클래스 변수는 자바 프로그램을 시작할 때 딱 1개가 만들어지고 인스턴스와는 다르게 보통 여러 곳에서 공유하는 목적으로 사용된다.
25. 더 자세히 지역 변수에 대해 설명하자면? ⇒ 지역 변수는 스택 영역에 있는 스택 프레임 안에 보관된다. 메소드가 종료되면 스택 프레임도 제거되는데 이 때 해당 스택 프레임에 포함된 지역 변수도 함께 제거된다. 그래서 지역 변수는 변수 생명주기가 가장 짧다.
26. 더 자세히 인스턴스 변수에 대해 설명하자면? ⇒ 인스턴스에 있는 멤버 변수를 인스턴스 변수라한다. 인스턴스 변수는 힙 영역을 사용한다. 힙 영역은 GC가 발생하기 전까지는 생존하기에 보통 지역 변수보다 생존 주기가 길다.
27. 더 자세히 클래스 변수에 대해 설명하자면? ⇒ 클래스 변수는 메소드 영역의 static 영역에 보관된는 변수다. 메소드 영역은 프로그램 전체에서 사용하는 공용 공간이다. 클래스 변수는 해당 클래스가 JVM에 로딩되는 순간 생성되고 JVM이 종료될 때까지 생명주기가 이어진다. 그래서 가장 긴 변수 생명주기를 가진다. 
28. static 변수는 접근법이 어떻게 된는가? ⇒ static변수는 클래스를 통해 바로 접근할 수도 있고, 인스턴스를 통해서도 접근할 수 있다. 
29. static 변수의 경우 인스턴스를 통한 접근은 추천하지 않는 이유는 무엇인가? ⇒ static 변수의 경우 인스턴스를 통한 접근은 추천하지 않는다 왜냐하면 코드를 읽을 때 마치 인스턴스 변수에 접근하는 것처럼 오해할 수 있기 때문이다.
30. static 변수는 왜 클래스를 통해 접근하는 것이 좋은가? ⇒ static 변수는 클래스에서 공용으로 관리하기에 클래스를 통해서 접근하는 것이 더 명확하기에 static 변수에 접근할 때는 클래스를 통해 접근하는 것이 좋다.
