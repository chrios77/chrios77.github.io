```
1. 라이브러리란? ⇒ 여러 클래스를 모아 둔 클래스의 모음을 말한다.
2. java.lang 패키지란? ⇒ 자바가 기본으로 제공하는 라이브러리 중에 가장 기본이 되는 것이 java.lang 패키지이다. 쉽게 말해서 자바 언어를 이루는 가장 기본이 되는 클래스들을 보관하는 패키지를 뜻한다.
3. java.lang 패키지에서 lang은 뭘 의미하는가? ⇒ language를 의미한다.
4. java.lang 패키지의 대표적인 클래스는 무엇인가? ⇒ Object, String, Integer, Long, Double, Class, System이 있다.
5. Object 클래스란? ⇒ 모든 자바 객체의 최상위 부모 클래스이다.
6. String 클래스란? ⇒ 문자열을 나타내는 클래스이다.
7. Integer, Long, Double 은 뭐라고 하는가? ⇒ 이런 것을 래퍼 타입이라고 하고, 기본형 데이터 타입을 객체로 만든 것이다.
8. Class 클래스는 무엇인가? ⇒ 클래스의 메타 정보를 나타내는 클래스이다.
9. System 클래스란? ⇒ 시스템과 관련된 기본 기능들을 제공한다.
10. java.lang 패키지를 사용할 때 import를 일일이 다 적어줘야 하는가? ⇒ java.lang 패키지는 모든 자바 애플리케이션에 자동으로 임포트되기에 임포트를 생략시켜도 된다. 이유는 너무 자주 사용하기에 임포트를 안 해준 상태로 실행하면 잘 실행되는 것이다.
11. Object 클래스는 모든 클래스에 일일이 extends 키워드를 써서 상속시킴을 알려줘야 하는가? ⇒  클래스에 상속 받을 부모 클래스가 없으면 묵시적으로 Object 클래스를 상속받는다. 그래서 부모 클래스를 상속하지 않아도 모든 클래스에 자동으로 상속된다.
12. 묵시적이란? ⇒ 묵시적은 영어로 implicit이라고 하고 개발자가 코드에 직접 기술하지 않아도 시스템이나 컴파일러에 의해 자동으로 수행되는 것을 의미한다.
13. 명시적이란? ⇒ 명시적은 영어로 Explicit이라하고, 개발자가 코드에 직접 기술해서 작동하는 것을 의미한다.
14. toString 메소드는 어디에 존재하는 메소드인가? ⇒ toString 메소드는 Object 클래스에 존재하는 메소드이다.
15. 자바에서 Object 클래스가 최상위 부모 클래스인 이유는 무엇인가? ⇒ 모든 클래스가 Object 클래스를 상속받는 이유는 공통 기능을 제공하고, 다형성의 기본을 구현할 수 있게 해주기 때문이다.
16. Object 클래스를 사용하는 이유 중 하나인 공통 기능 제공은 무엇을 말하는가? ⇒ 객체의 정보를 제공하고 이 객체가 다른 객체와 같은지 비교하고, 객체가 어떤 클래스로 만들어졌는지 확인하는 기능은 모든 객체에게 필요한 기본 기능이다. 이런 기능을 객체를 만들 때마다 항상 새로운 메소드를 정의해서 만들어야 한다면 상당히 번거로울 것이고 만든다고 해도 개발자마다 다른 이름의 메소드를 만들어 일관성이 없을 것이다. 그러므로 Object 클래스를 만들어 모든 객체에 필요한 기능을 제공하는 것이고 Object 클래스는 최상위 부모 클래스이기에 모든 객체는 공통 기능을 편리하게 상속하여 제공받을 수 있다.
17. Object 클래스가 제공하는 기능은 무엇인가? ⇒ toString(), equals(), getClass() 등이 있다. toString()은 객체의 정보를 제공하는 메소드이고, equals()은 객체의 같음을 비교하는 메소드이고, getClass()는 객체의 클래스 정보를 제공하는 메소드이다.
18. Object 클래스를 사용하는 이유 중 하나인 ****다형성의 기본 구현은 무엇을 말하는 것인가? ⇒ 부모 클래스는 자식 클래스를 담을 수 있다. Object 클래스는 모든 클래스의 부모 클래스이기에 모든 객체를 참조할 수 있다. Object 클래스는 다형성을 지원하는 기본적인 메커니즘을 제공한다. 모든 자바 객체는 Object 타입으로 처리될 수 있고, 이는 다양한 타입의 객체를 통합적으로 처리할 수 있게 해준다. 쉽게 얘기해서 Object 클래스는 모든 객체를 다 담을 수 있기에 타입이 다른 객체들을 어딘가에 보관해야 한다면 Object 클래스에 보관하면 된다.
19. Object 클래스는 다형성을 어찌하는가? ⇒ Object 클래스는 모든 클래스의 부모 클래스이기에 모든 객체를 참조할 수 있다.
20. Object 클래스를 활용한 다형성의 장점은 무엇인가? ⇒ 어떤 객체든지 인자로 전달할 수 있다.
21. Object 클래스를 활용한 다형성의 한계는 무엇인가? ⇒ Object 클래스에 존재하지 않는 메소드는 다운 캐스팅을 해주지 않는 이상 활용할 수 없다. 그러므로 Object 클래스는 모든 객체의 부모기므로 모든 객체를 대상으로 다형적 참조는 가능하나, 메소드 오버라이딩이 안되기에 다형성을 활용하기에는 한계가 있다. 참고로 Object 클래스가 보유한 메소드는 당연히 자식 클래스에서 오버라이딩할 수 있다.
22. Object 배열이란? Object 클래스는 모든 타입의 객체를 담을 수 있기에 Object 배열, 즉, Object[]을 만들면 세상의 모든 객체를 담을 수 있는 배열을 만들 수 있다. 예를 들어, size(Object[] objects)라는 메소드를 만들어 배열에 담긴 객체의 수를 세는 역할을 맡긴다고 쳤을 때 Object타입의 배열은 세상의 모든 객체를 담을 수 있기에 새로운 클래스가 추가되거나 변경되어도 메소드를 수정하지 않아도 된다.
23. Object도 인스턴스로 만들 수 있는가? O/X ⇒ O
24. Object가 없다면 어찌될까? ⇒ 예를 들어, void action(Object obj)와 같은 모든 객체를 받을 수 있는 메소드를 만들 수 없다. 또한, Object[] objects처럼 모든 객체를 저장할 수 있는 배열을 만들 수 없다. 물론 Object가 없어도 직접 MyObject 같은 클래스를 만들고 모든 클래스에서 직접 정으한 MyObject를 상속받으면 되지만 하나의 프로젝트를 넘어 전세계 모든 개발자가 비슷한 클래스를 만들 것이고, 서로 호환되지 않는 수 많은 Object들이 넘쳐날 것이다.
25. toString이란? ⇒ Object 클래스에는 toString이라는 메소드가 존재한다. 이 메소드는 객체의 정보를 문자열 형태로 제공한다. 그래서 디버깅과 로깅에 유용하게 사용된다.  또한 이 메소드는 Object 클래스에 정의되어 있기에 모든 클래스에서 상속받아 사용할 수 있다.
26. toString은 몇 진수로 제공하는가? ⇒ toString 메소드는 기본적으로 패키지를 포함한 객체의 이름과 객체의 참조값으로 들어간 해시코드를 16진수로 제공한다.
27. println()과 toString()? ⇒ println은 내부에서 toString을 호출한다. 그래서 이 println으로 나타낸 코드의 값이 toString을 사용하여 나타낸 코드의 값과 비슷한 것이다.
28. toString()에 오버라이딩하는 이유는 무엇인가? ⇒ toString() 메소드가 클래스 정보와 참조값을 제공하긴 하지만 이 정보만으로는 객체의 상태를 적절히 나타내지 못한다. 그래서 보통 toString()을 재정의해서 보다 유용한 정보를 제공하는 것이 일반적이다.
29. 객체의 참조값을 직접 출력하는 경우는? ⇒ toString() 메소드는 기본으로 객체의 참조값을 출력한다. 그런데 toString()나 hashCode() 메소드를 재정의하면 객체의 참조값을 출력할 수 없다. 이럴 때는 String refValue = Integer.toHexString(System.identityHashCode(dog1));처럼 해주고 실행해보면 16진수로 객체의 참조값을 출력할 수 있다.
```
