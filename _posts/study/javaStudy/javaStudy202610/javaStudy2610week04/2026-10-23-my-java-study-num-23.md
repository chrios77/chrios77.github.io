1. Object가 없고, Object가 제공하는 toString이 없다면 어찌되겠는가? ⇒ 만약 Object가 없고, Object가 제공하는 toString이 없다면 서로 아무 관계가 없는 객체의 정보를 출력하기 어려울 것이다. 여기서 아무 관계가 없다는 것은 공통의 부모가 없다는 뜻이다. 그렇게 되면 아마 각각의 클래스마다 별도의 메소드를 작성해야 할 것이다.

3. 자바에는 객체의 정보를 사용할 때 다형적 참조 문제와 메소드 오버라이딩 문제를 해결해줄 어떤 것이 존재하는가? ⇒ 전자로는 Object 클래스, 후자로는 toString 메소드가 존재한다.
4. Obect나 toString이 없는 상태에서 추상적인 타입에 의존하게 되면 어찌 되는가? ⇒ Obect나 toString이 없는 상태에서 추상적인 타입에 의존하게 되면 어떤 클래스가 구체적인 클래스를 사용하는 것이 아니라 추상적인 Object 클래스를 사용하면, 어떤 클래스가 Object 클래스를 사용하는 것을 Object 클래스에 의존한다고 표현한다.

6. 다형성을 잘 활용한다는 것은 무엇을 말하는가? ⇒ 다형성을 잘 활용한다는 것은 다형적 참조와 메소드 오버라이딩을 적적하게 사용한다는 뜻이다.
7. OCP원칙이란? ⇒ OCP 원칙은 영어로 Open-Closed Principle이라고 하고 현재 배우는 것에 대입해보면, Open은 새로운 클래스를 추가하고 toString을 오버라이딩해서 기능을 확장할 수 있다. Closed는 새로운 클래스를 추가해도 Object와 toString을 사용하는 클라이언트 코드는 변경하지 않아도 된다.
8. System.out.println()은 어찌 동작하는가? ⇒ System.out.println() 메소드는 Object 매개변수를 사용하고 내부에서 toString을 호출한다. 따라서 System.out.println() 메소드를 사용하면 세상의 모든 객체의 정보를 편리하게 출력할 수 있다.
9. 자바는 객체지향 언어 답게 자바 스스로도 객체지향의 특징을 매우 잘 활용한다? O/X ⇒ O, 예를 들어 toString 메소드처럼, 자바 언어가 기본으로 제공하는 다양한 메소드들은 개발자가 필요에 따라 오버라이딩해서 사용할 수 있도록 설계되어 있다.
10. 정적 의존관계란? ⇒ 정적 의존관계는 컴파일 시간에 결정되며, 주로 클래스 간의 관계를 의미한다.
11. 동적 의존관계란? ⇒ 동적 의존관계는 프로그램을 실행하는 런타임에 확인할 수 있는 의존관계이다.
12. 의존관계 혹은 어디에 의존한다고 하면 주로 뭘 뜻하는가? ⇒ 의존관ㄱ계 혹은 어디에 의존한다고 하면 주로 정적 의존관계를 뜻한다.
13. Object는 동등성 비교를 위해 어떤 메소드를 제공하는가? ⇒ equals() 메소드
14. 동일성과 동등성이란 무엇인가? ⇒ 동일성이란 ==연산자를 사용해서 두 객체의 참조가 동일한 객체를 가리키고 있는 지 확인하는 것이다. 동등성은 equauls() 메소드를 사용해서 두 객체가 논리적으로 동등한지 확인하는 것이다. 
15. 동일성과 동등성을 구체적으로 설명하면 뭐라고 하겠는가? ⇒ 동일은 완전히 같음을 의미하고, 동등은 같은 가치나 수준을 의미하지만 그 형태나 외관 등이 완전히 같지는 않을 수 있다. 즉, 동일성은 물리적으로 같은 메모리에 있는 객체 인스턴스인지 참조값을 확인하는 것이고, 동등성은 논리적으로 같은지 확인하는 것이다. 동일성은 자바 머신 기준이고 메모리의 참조가 기준이므로 물리적이다. 반면, 동등성은 보통 사람이 생각하는 논리적인 기준에 맞추어 비교한다. 
16. 동등성이라는 개념은 각각의 클래스마다 다른가? O/X ⇒ O, 동등성이라는 개념은 각각의 클래스마다 다른다. 어떤 클래스는 주민등록번호를 기반으로 동등성을 처리할 수 있고, 어떤 클래스는 고객의 연락처를 기반으로 동등성을 처리할 수 있다. 어떤 클래스는 회원 번호를 기반으로 동등성을 처리할 수 있다. 따라서 동등성 비교를 사용하고 싶으면 equals() 메소드를 재정의해야 한다. 그렇지 않으면 Object는 동일성 비교를 기본으로 제공한다.
17. 인텔리제이는 equals() 메소드를 alt + insert 하여 equals를 equals() and hashCode() 파트를 선택하면 자동으로 만들어주는가? O/X ⇒ O  
18. equals() 메소드를 구현할 때 지켜야 하는 규칙은 무엇인가? ⇒ 반사성, 대칭성, 추이성, 일관성, null에 대한 비교이다. 
19. equals() 메소드를 구현할 때 지켜야 하는 규칙 중 하나인 반사성이란 무엇인가? ⇒ 반사성은 영어로 Reflexivity라하고, 이는 객체는 자기 자신과 동등해야 한다는 것이다. 예를 들어, x.equals(x)는 항상 true이다.
20. equals() 메소드를 구현할 때 지켜야 하는 규칙 중 하나인 대칭성이란 무엇인가? ⇒ 대칭성은 영어로 Symmetry라고 하고, 두 객체가 서로에 대해 동인하다고 판단하면, 이는 양방향으로 동일해야 한다는 것이다. 예를 들어, x.equals(y)가 true이면 y.equals(x)도 true이다.
21. equals() 메소드를 구현할 때 지켜야 하는 규칙 중 하나인 추이성이란 무엇인가? ⇒ 추이성은 영어로 Transitivity라고 하고 이는 만약 한 객체가 두 번째 객체와 동일하고 두 번째 객체가 세 번째 객체와 동일하다면, 첫 번째 객체는 세번째 객체와도 동일해야 한다는 것이다.
22. equals() 메소드를 구현할 때 지켜야 하는 규칙 중 하나인 일관성이란 무엇인가? ⇒ 일관성이란 영어로 Consistency라고 하고, 두 객체의 상태가 변경되지 않는 한, equals() 메소드는 항상 동일한 값을 반환해야 한다는 것이다.
23. equals() 메소드를 구현할 때 지켜야 하는 규칙 중 하나인 null에 대한 비교는 무엇인가? ⇒ null에 대한 비교는 모든 객체는 null과 비교했을 때 false를 반환해야 한다는 것이다.
24. 동일성 비교가 항상 필요한가? O/X ⇒ X, 동일성 비교가 항상 필요한 것은 아니다. 동일성 비교가 필요한 경우에만 equals() 메소드를 재정의하면 된다.

27. 기본형과 참조형의 공유란? ⇒ 자바의 데이터 타입을 크게 보면 기본형과 참조형으로 나눌 수 있다. 기본형은 하나의 값을 여러 변수에서 절대로 공유하지 않는다. 반면, 참조형은 하나의 객체를 참조값을 통해 여러 변수에서 공유할 수 있다. 
28. 사이드 이펙트란? ⇒ 사이드 이펙트는 영어로 Side Effect라고 하고, 프로그래밍에서 어떤 계산이 주된 작업 외에 추가적인 부수 효과를 일으키는 것을 말한다. 주로 공유 참조로 인해 일어난다. 프로그래밍에서 사이드 이펙트는 보통 부정적인 의미로 사용되는데, 사이드 이펙트는 프로그램의 특정 부분에서 발생한 변경이 의도치 않게 다른 부분에 영향을 미치는 경우에 발생한다. 이로 인해 디버깅이 어려워지고 코드의 안정성이 저하될 수 있다.
29. 사이드 이펙트의 해결방안은 무엇인가? ⇒ 해결 방안은 아주 단순하다. 예를 들어, 참조 타입 변수 같은 것을 참조할 때 처음부터 서로 다른 인스턴스로 참조하면 된다.  
30. 사이드 이펙트를 해결할 때 어쩔 수 없는 부분은 무엇인가? ⇒ 사이드 이펙트를 해결할 때 같은 인스턴스를 변수가 함께 공유하기에 발생한 문제였기에 객체를 공유하지 않으면 문제가 해결된다. 따라서 변수가 서로 각각 다른 주소지로 변경할 수 있어야 한다. 이렇게 하려면 서로 다른 객체를 참고하면 된다. 그러나 사이드 이펙트를 해결할 떄 여러 변수가 하나의 객체를 공유하는 것을 막을 방법은 없다. 심지어 에러도 나지 않는다. 그저 참조값을 공유하는 것일뿐 자바 문법상 문제가 있는 것이 아니기 때문이다.
