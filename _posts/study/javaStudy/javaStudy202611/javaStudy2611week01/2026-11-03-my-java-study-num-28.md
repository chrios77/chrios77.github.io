```
1. String 사용 시 타입 안정성 부족 문제가 발생할 수도 있는데 이 때 발생하는 문제는 무엇인가? ⇒ 값의 제한 부족, 컴파일 시 오류 감지 불가, 이것들은 각각 String으로 상태나 카테고리를 표현하면 잘못된 문자열을 실수로 입력할 가능성이 있고, 이러한 잘못된 값은 컴파일 시에는 감지되지 않고, 런타임에서만 문제가 발견되기에 디버깅이 어려워질 수 있다는 단점을 말한다.
2. String 사용시 타입 안정성 부족 문제을 해결하려면 어찌해야 하는가? ⇒ 이런 문제를 해결하려면 특정 범위로 값을 제한해야 한다. 예를 들어, BASIC, GOLD, DIAMOND라는 정확한 문자만 discount() 메소드에 전달되어야 한다. 하지만 String은 어떤 문자열이든 받을 수 있기에 BASIC이라고 하든 basic이라고 하든 자바 문법 관점에서는 아무런 문제가 없다. 따라서 String 타입을 사용해서는 문제를 해결할 수 없다.
3. 문자열을 상수로 사용하면 어떤가? ⇒ 문자열 상수를 사용한 덕분에 전체적으로 코드가 더 명확해진다. 그리고 예를 들어, discount() 메소드에 인자를 전달할 때도 StringGrade가 제공하는 문자열 상수를 사용하면 된다. 더 좋은 점은 만약 실수로 상수의 이름을 잘못 입력하면 컴파일 시점에 오류가 발생한다는 점이다. 따라서 오류를 쉽고 빠르게 찾을 수 있다. 하지만 문자열 상수를 사용해도 발생한 문제를 근본적으로 해결할 수는 없다. 왜냐하면 String 타입은 어떤 문자열이든 입력할 수 있기 때문이다. 어떤 개발자가 실수로 StringGrade에 있는 문자열 상수를 사용하지 않고 직접 문자열을 사용해도 막을 수 있는 방법이 없다.
4. 타입 안전 열거형 패턴이란 무엇인가? ⇒ 일단 타입 안전 열거형 패턴은 Type-Safe Enum Pattern이라고 하고, String 사용 시 발생하는 타입 안전성 부족 문제 등을 해결하기 위해 많은 개발자들이 오랜 기간 고민해 나온 결과이다. 우선, enum은 enumeration의 줄임말이며 이는 사전적으로 열거라는 뜻이고, 어떤 항목을 나열하는 것을 뜻한다. 예를 들어, 회원 등급인 BASIC, GOLD, DDIAMOND를 나열하는 것이다. 중요한 것은 타입 안전 열거형 패턴을 사용하면 나열한 항목만 사용할 수 있다는 것이 핵심이고 나열한 항목이 아닌 것은 사용할 수 없다. 쉽게 말해 String처럼 아무런 문자열이나 다 사용할 수 있는 것이 아니라, 예시에 나열한 항목인 BASIC, GOLD, DIAMOND만 안전하게 사용할 수 있다는 것이다. 
5. 타입 안전 열거형 패턴의 장점은 무엇인가? ⇒ 타입 안전 열거형 패턴의 장점은 타입 안정성 향상, 데이터 일관성이다. 각각 정해진 객체만 사용할 수 있기에, 잘못된 값을 입력하는 문제를 근본적으로 방지할 수 있고, 정해진 객체만 사용하므로 데이터의 일관성이 보장된다는 의미이다.
6. 타입 안전 열거형 패턴의 장점을 더 자세히 설명하자면? ⇒ 타입 안전 열거형 패턴의 장점을 더 자세히 설명하자면 제한된 인스턴스 생성, 타입 안정성이다. 전자는 클래스는 사전에 정의된 몇 개의 인스턴스만 생성하고, 외부에서는 이 인스턴스들만 사용할 수 있도록 한다. 이를 통해 미리 정의된 값들만 사용하도록 보장한다는 의미이고, 후자는 이 패턴을 사용하면, 잘못된 값이 할당되거나 사용되는 것을 컴파일 시점에 방지할 수 있다는 것이다. 예를 들어, 특정 메소드가 특정 열거형 타입의 값을 요구한다면, 오직 해당 타입의 인스턴스만 전달할 수 있다.
7. 타입 안전 열거형 패턴의 단점은 무엇인가? ⇒ 이 패턴을 구현하려면 public static final ClassGrade BASIC = new ClassGrade();처럼 많은 코드를 작성해야 한다. 그리고 private 생성자를 추가하는 등의 유의해야 하는 부분도 있다. 
8. 열거형이란? ⇒ 일단 열거형은 영어로 Enum Type이라고 하고, 타입 안전 열거형 패턴의 단점에도 불구하고 개발자들이 많이 사용하자 생겨났다. 열거형 타입은 자바에서 타입 안전 열거형 패턴을 매우 편리하게 사용할 수 있게 제공하는 것이다. enum은  enumeration의 줄임말이다. enumeration은 일련의 명명된 상수들의 집합을 정의하는 것을 의미하고, 프로그래밍에서는 이러한 상수들을 사용하여 코드 내에서 미리 정의된 값들의 집합을 나타낸다. 쉽계 예를 들면 회원의 등급은 상수로 정의한 BASIC, GOLD, DIAMOND만 사용할 수 있다는 뜻이다.
9. 자바의 enum은 뭘 제공하는가? ⇒ 자바의 enum은 타입 안정성을 제공하고, 코드의 가독성을 높이며, 예상 가능한 값들의 집합을 표현하는데 사용된다.
10. 열거형을 정의할 때는 뭘 사용하는가? ⇒ 열거형을 정의할 때는 class 대신 enum를 사용하고 그 후 코드로 원하는 상수의 이를을 나열하면 된다. 예를 들어, public class Grade {}를 public enum Grade {}라고 적어주면 열거형으로 나타낼 수 있다.
11. 열거형의 특징은 무엇인가? ⇒ 첫째, 열거형도 클래스이다. 둘째, 열거형은 자동으로 java.lang.Enum을 상속 받는다. Enum 클래스를 상속받기에 추가로 다른 클래스를 상속받을 수 없다. 셋째, 외부에서 임의로 생성할 수 없다. 넷째, switch문에도 사용 가능하다. 다섯째, 열거형 내부에서 상수로 지정하는 것 외에 직접 생성이 불가능하다. 만약 생성할 경우 오류가 발생한다. 여섯째, 열거형은 인터페이스를 구현할 수 있다. 일곱째, 열거형에 추상 메소드를 선언하고, 구현할 수 있다. 이 경우 익명 클래스와 같은 방식을 사용한다. 여덟 째, 리팩토링할 수 있다.
12. 열거형의 장점은 무엇인가? ⇒ 열거형의 장점은 타입 안정성 향상, 간결성 및 일관성, 확장성이다. 첫 번째 장점은 열거형은 사전에 정의된 상수들로만 구성되므로, 유효하지 않은 값이 입력될 가능성이 없다. 이런 경우 컴파일 오류가 발생한다는 것이고, 2번째 장점은 열거형을 사용하면 코드가 더 간결하고 명확해지며, 데이터의 일관성이 보장된다는 것이다. 3번째 장점은 예를 들어, 새로운 회원 등급을 추가하고 싶을 때, ENUM에 새로운 상수를 추가하기만 하면 된다는 의미이다.
13. 열거형에 대해 참고할 사항은 무엇인가? ⇒ 참고로 열거형을 사용하는 경우 static import를 적절하게 사용하면 더 읽기 좋은 코드를 만들 수 있다.
14. 모든 열거형은 java.lang.Enum 클래스를 자동으로 상속받는가? O/X ⇒ O. 모든 열거형은 java.lang.Enum 클래스를 자동으로 상속받는다. 따라서 해당 클래스가 제공하는 기능들을 사용할 수 있다.
15. 열거형의 주요 메소드는 무엇인가? ⇒ 열거형의 주요 메소드는 values() 메소드, valueOf(String name) 메소드, name() 메소드, ordinal() 메소드, toString() 메소드가 있다. 
16. 열거형의 주요 메소드인 values() 메소드는 어떤 기능을 하는 메소드인가? ⇒ 열거형의 주요 메소드인 values() 메소드는 모든 ENUM 상수를 포함하는 배열을 반환한다.
17. 열거형의 주요 메소드인 valueOf(String name) 메소드는 어떤 기능을 하는 메소드인가? ⇒ 열거형의 주요 메소드인 valueOf(String name) 메소드는 주어진 이름과 일치하는 ENUM 상수를 반환한다.
18. 열거형의 주요 메소드인 name() 메소드는 어떤 기능을 하는 메소드인가? ⇒ 열거형의 주요 메소드인 name() 메소드는 ENUM 상수의 이름을 문자열로 반환한다..
19. 열거형의 주요 메소드인 ordinal() 메소드는 어떤 기능을 하는 메소드인가? ⇒ 열거형의 주요 메소드인 ordinal() 메소드는 ENUM 상수의 선언 순서를 반환한다. 이 때, 선언 순서는 0부터 시작한다. 
20. 열거형의 주요 메소드인 toString() 메소드는 어떤 기능을 하는 메소드인가? ⇒ 열거형의 주요 메소드인 toString() 메소드는 ENUM 상수의 이름을 문자열로 반환한다. name() 메소드와 유사하나, toString() 메소드는 직접 오버라이드할 수 있다.
21. 열거형의 주요 메소드인 ordinal() 메소드와 관련해서 주의할 것은 무엇인가? ⇒ 열거형의 주요 메소드인 ordinal() 메소드는 가급적이면 사용하지 않는 것이 좋다. 왜냐하면 이 값을 사용하다가 중간에 상수를 선언하는 위치가 변경되면 전체 상수의 위치가 모두 변경될 수 있기 때문이다. 예를 들어 중간에 BASIC 다음에 SLIVER 등급이 추가되는 경우 GOLD, DIAMOND의 값이 하나씩 추가해야 하는 것을 들 수 있다. 이렇게 되면 DB나 파일에 있는 값은 1로 유지되지만, 애플리케이션 상에서 GOLD는 2가 되고, SLIVER는 1이 된다. 그렇게 되면 기존 GOLD 회원이 SLIVER 가 되는 버그가 생길 수 있다.
```
